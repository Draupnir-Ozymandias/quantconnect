# Packed validity-probe cost declaration

This is a distinct experiment, not a repair or replay of the rejected original
cost cohort. The original plan, thresholds, source and rejection remain intact.
Declaration, trial, launcher and auditor have separate source-bound schemas and
private `/var/lib/qcrl-stream/receive-loop-packed-<suffix>` staging with
`qcrl-packed-<suffix>` units. Fixture-only integration remains a separate module.

## Unchanged controls

Nine cases in three rotated rounds; control/pacing/full order; six 4-second
500/s and 1-second 3,000/s cycles; 30,000 deterministic deliveries per case;
no sockets. Identical generator/preparation and raw-reference sink across lanes.
Wall reads remain 4/7/11 per step plus initialization; full takes two thread CPU
samples per step. The observer, fixed wake schedule, identity/counter checks,
native resource method, 100%/25% worker/observer CPU quotas, 512 MiB memory,
32 tasks, 120-second unit bounds and dedicated live PID/cgroup handshake remain.

All original acceptance thresholds and unknown/reject precedence remain:
combined actor CPU ratio <=1.05, sampled high-water RSS ratio <=1.10, individual
phase-window added p99 <=1 ms and added worst <=5 ms. All absolute attainment,
lateness, clock brackets, raw populations and counter checks remain mandatory.
No pooling, threshold tuning, resource adjustment, replay or automatic retry.

## Declared intervention

Packed double columns replace retained row and CPU-stamp objects. Per-step
callback closures and partition/result dictionaries are removed. Finite/order,
identity, CPU reset/enclosure and capacity checks remain inline; partition
construction/conservation validation moves after the collection window. Global
wall ordering is stricter than the original CPU-stamp path. Coverage and call
counts are retained, but validation failure timing is not identical.

Snapshots retain both the versioned prototype wrapper and canonical core outside
collection. The 32 MiB sideband gate uses canonical core without raws plus
observer JSON, as before; redundant wrapper serialization is not double-counted.
Snapshot failure retains raw evidence and cannot become a successful case.
Sampled RSS remains process-lifetime high-water through the samples, not current
RSS or a collection-window peak; actor maxima are summed without deduplication.

## Freeze and advancement

Declaration generation is offline and exclusive. It binds the exact source file
bytes, policy, packed method and predecessor rejection audit. Implemented code
does not imply executed or accepted measurements. Declaration execution,
benchmark, cost-acceptance, rollout and order flags remain false. The explicit
Linux launcher is the execution boundary, not the declaration.

Before any cohort: pass offline correctness/fault tests; commit/source-freeze;
validate the saved declaration against that checkout; pass a fresh native tiny
live-unit smoke; obtain finite-cohort execution authorization. The launcher also
requires a clean private qcrl-owned Git checkout, four GiB free and unchanged
public collector prerequisites. It captures and preserves only its own units.

Independent audit requires an externally obtained inventory byte hash and exact
commit, verifies source/input/ordered raw/prototype/unit/window links, and checks
origin bytes before and after fixed-threshold evaluation. Even a pass advances
only to a separately declared validity workload, not recorder or trading approval.

## Offline implementation verification — October 10

All **845 local regression tests passed**, including 29 dedicated declaration,
trial, launcher and auditor tests. Production staging requires live bindings and
the full 30,000-step schedule; tiny fixtures cannot count as real cohort evidence.
Tests explicitly compare preserved gates/workload/quotas against v1 and reject
original inventory schemas in the new auditor. No native unit smoke or packed
cost experiment has been run. These files still require commit/source-freeze
before cloud execution; source edits invalidate a previously saved declaration.
